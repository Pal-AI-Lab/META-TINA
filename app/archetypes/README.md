# Archetype Library

An archetype is an app's "shape": the combination of its core loop, its
state form, and its verification style. The primary archetype is fixed
during the admission interview; mixing is allowed (primary + secondary,
e.g. "builder primary, tracker secondary": take the primary archetype's
skeleton and borrow individual fixtures from the secondary); when nothing
fits, fall back to generic.md — and take a moment to reconsider whether
"what is the artifact?" was really thought through at admission.

## The four archetypes in one line each

- **builder** — accompany the user in making something that runs
  (software, mods, scripts);
- **generator** — produce documents or assets from the user's inputs;
- **mentor** — guide the user through a real-world process or skill;
- **tracker** — keep a reliable long-term ledger for the user (status,
  progress, deadlines) and answer truthfully.

## Structure of each archetype file

Definition & examples / core loop / state-area shape / DoD shape /
supplementary extraction questions / archetype-specific risks / skeleton
notes. When entering the extraction and assembly phases, the relevant
archetype file is required reading.
