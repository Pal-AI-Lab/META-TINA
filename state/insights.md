# Insights — 项目复盘,Meta TINA 自改的原料

## 2026-09-12 — cortico-extension-creator,准入阶段
- 现象:agent 把七项预填草稿加十条拍板清单一次交给专家,并用「第 7 项」这种文件内编号指代;专家不知所指。
- 1-admission.md 已写「不要像问卷一样发问,一问接一问」,但没覆盖「专家就是代码作者、agent 能从代码预填」的情形:预填的草稿不该整份交给专家读,要在对话里逐条带背景确认。
- 候选改动(待专家同意,I4):1-admission.md 加一句——预填内容逐条口头确认;每一问自带背景,不用编号或文件位置指代。
- 专家的定位:造这个 Creator 的过程同时是调整 TINA spec 与 Meta TINA 的过程。spec 自己也说:草案标记要等第一个真实应用跑通才摘。
- 已改(专家提出并同意,I4):1-admission.md 第 7 问从「回忆带新手的经历」改成「不熟悉的人容易出什么问题、按什么纠正」,带新手只作为一种问法的例子。理由:原问法过于具体,把一种取材方式当成了问题本身。
- 抽取阶段缺一道筛子:专家答「这有必要写进去吗?coding agent 的常识完全可以决定」。候选改动(待同意,I4):2-extraction.md 加一条——每条知识过一遍「没有这份文档,一个胜任的 agent 会不会自己做对」,会的不写;输出 TINA 只装 runtime 自己得不出的判断。
- 已改(专家提出并同意,I4):builder.md 状态区形状加一段——工作区交付后继续作为产物的维护目录长期存在;本身要成为独立仓库的产物从第一天起自带 git、工作区 gitignore 它、只存档 design/ 与日志。workspace-conventions.md §7 加对应一句。理由:Meta TINA 原先把产物当成状态区里的副产品、发布时才独立;对包 / 模组这类产物,开发者中途就要推自己的仓库,而且工作区不会随交付结束。
- 试驾直接在 workspace/ 里跑,首次运行按 AGENTS 建了 .git,外层 git 从此把 workspace/ 当内嵌仓库,装配后的修改失去存档轨迹。已改(专家定,I4):试驾建 .git 是预期行为(coding agent 开项目常自动 git init);5-testdrive.md 加「清场」一节——每趟之后删 workspace/.git 与试驾产生的状态,恢复模板,确认外层 git 重新看见 workspace/。
